Durable execution, entirely in this tab

Everything below runs the production AgentIQ runtime — real DBOS, real pgx, the real generated client — compiled to WebAssembly. The database is a real PostgreSQL 19 engine (a PGlite fork) running beside it, reached over a net.Conn that speaks the PostgreSQL wire protocol through execProtocol instead of a socket. There is no server.

Start a workflow, then reload the tab while it is still PENDING. The workflow sleeps for two seconds between its two steps; reloading during that window kills the worker. When the page comes back, DBOS finds the run in IndexedDB-persisted Postgres and resumes it from the last checkpoint — the first step is not re-executed.

Failure-matrix row F20: invalid SQL must come back as a real pgx error with its SQLSTATE intact, not as a lost frame or a torn connection. Press Run invalid SQL above.

Known gap

PGlite is a single backend session, and the multiplexer gives several logical connections a share of it. A transaction is session-scoped, so one connection can commit another's — an enqueued workflow reaches PENDING and its first step then fails with RELEASE SAVEPOINT can only be used in transaction blocks. Everything above this point — the migrations, the property graph, the queue, the enqueue — works. The fix is in the transport, not the page; see the package comment in demo/wasm/main.go.
